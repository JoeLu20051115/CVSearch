# 分阶段自适应视觉搜索方法报告设计

## 1. 报告目标

新报告面向第一次接触本项目、但了解视觉问答基本概念的读者。报告需要沿真实执行顺序说明当前已经验证的方法，重点回答四个问题：候选区域从哪里来、为什么这样排序、后续观察如何补充证据，以及为什么最终答案可以安全地替换或回退。

报告使用中文，保留必要的英文接口名，如 `ZOOM`、`EXPAND`、`SPLIT`、`CONTINUE`、`BACKTRACK`、`REPLACE` 和 `P0`。每个名称在第一次出现时用普通语言解释。正文不使用没有对应代码、配置或实验材料的新名称。

最终交付包括可编辑源文件和编译后的 PDF。版式模仿现有《Query 感知、证据缺口引导的自适应视觉搜索》：A4 纵向、深蓝标题、青绿色强调色、浅色说明框、页眉与页码、少量公式、流程图和低墨量结果表。

## 2. 方法边界和术语

报告将当前系统分为四个连续部分。这里的分工是叙事和实现边界，不把后续收益错误归因给 Stage 1。

1. **Stage 1：候选生成与排序。** 输入原图和问题，执行全图快速判断、目标提取、SAM 3 定位、必要时的语义区域树构建、CVSearch 初始排序和 Query 感知重排。输出冻结的候选顺序和初始观察记录。
2. **Stage 2：尺度与上下文观察。** 从 Stage 1 候选出发，用 `ZOOM` 补充同一区域的分辨率，用 `EXPAND` 补充相邻上下文，并结合支持度、答案一致性和校准结果选择 Stage 2 答案。该答案及其来源区域被完整保存，作为后续阶段的保守锚点 `P0`。
3. **Stage 3：受限分支搜索。** 在 `P0` 仍可能缺少局部证据时，用 `SPLIT` 产生有限分支和多尺度观察。控制器根据答案不确定性、多视图一致性、校准支持度、支持增量和与 `P0` 的冲突程度，在 `CONTINUE`、`BACKTRACK`、`REPLACE` 和保留 `P0` 之间选择。
4. **独立验证层。** Qwen2.5-VL-32B 只接收原图、原问题和选项，不接收 `P0` 或 Stage 3 候选。它提供一个独立全图答案，用于否决不一致的候选，或在严格一致条件下确认可恢复的候选。任何解析、材料绑定或运行异常都精确返回 `P0`。

原 PDF 中的 DiNCo-inspired 三次问询公式属于早期设计，不作为当前实现原样保留。新报告只保留其“答案不确定性与独立证据分开计算”的思想，并按当前实现描述多视图答案一致性、校准支持度和候选无关的独立全图答案。

报告正文约 15 页，各页只传达一个主要信息。

### 第 1 页：封面与一句话方法

- 放置一个四段式缩略流程：Stage 1 → Stage 2 → Stage 3 → 独立验证。

### 第 2 页：问题背景、方法目标与贡献边界

- 解释高分辨率图像中全图缩放会丢失小目标，穷举局部区域又会增加成本。
- 明确继承项：CVSearch 的全图判断、目标提取、SAM 3、语义区域树和层级搜索骨架。
- 明确本项目改动：Query 感知排序、问题自适应权重、可审计 Observation、校准支持度、保守 `P0` 回退、Stage 3 风险控制和独立全图验证。
- 不把候选生成器、SAM 3 或基础 MLLM 训练表述为本项目贡献。

### 第 3 页：完整系统流程图与四部分分工

```text

Stage 1：候选生成与排序
全图判断 → 目标提取 → SAM 3 → 语义区域树
→ CVSearch 初始排序 → Query 感知重排
    │
    ▼

ZOOM / EXPAND → 支持度与答案一致性

    │

    ├── 支持安全候选 → 接受候选
    └── 运行或材料异常 → 精确返回 P0
```

### 第 4 页：Stage 1——全图判断、目标提取与 SAM 3 定位

- 从整图回答置信度开始；足够高时直接回答，不进入区域搜索。
- 置信度不足时，从问题中提取需要定位的视觉目标，并清理代词和集合表达。
- SAM 3 成功时直接得到目标框，形成快速搜索区域。
- SAM 3 只成功定位部分目标时，成功目标保留，失败目标进入语义区域树路径。

### 第 5 页：Stage 1——SAM 失败后的语义区域树

- 用 SAM 3 的图像特征构建约 600 个相邻视觉原子。
- 在语义特征和位置特征上做受连通性约束的层次聚类；每次在 4 至 8 个子簇中选择轮廓系数高、区域重叠较少的划分。
- 区域复杂度来自内部特征差异；复杂度过低的区域不继续细分。
- 单目标搜索最多使用两层，多目标或关系搜索最多使用三层。
- 本页用一张“整图 → 粗区域 → 细区域”的树图解释区域如何形成，不引入新的区域生成术语。

### 第 6 页：Stage 1——CVSearch 初始排序

- 先说明低先验区域会跳过昂贵的存在性评估；其余区域由基础 MLLM 判断目标是否存在。
- 当前区域存在置信度、子区域聚合置信度和区域先验共同形成 CVSearch 排序分数。
- 有子区域信息时使用：

  `S_cv = 0.4 C_current + 0.4 C_child + 0.2 P_prior`。

- 最深层没有可靠子区域信息时，只在当前存在置信度和区域先验之间重新归一化权重。
- 强调该分数是 Query 感知重排之前的初始访问顺序，也是后续对比基线。

### 第 7 页：Stage 1——Query 感知重排与问题自适应权重

- 主 Query 是原问题；定位表达来自当前视觉目标，例如 `locate and inspect <target>`。
- 每个候选计算四个可直接解释的量：主问题 CLIP 相似度、定位表达 CLIP 相似度、区域复杂度和边缘密度。
- 四个量先在同一批候选内转为百分位，避免原始量纲不一致。
- 基本融合为：

  `R = β C_main + (1-β) C_aug`，

  `V = λ C_complexity + (1-λ) C_edge`，

  `S_rank = α R + (1-α) V`。

- 冻结 v6 参数为 `β=0.60`、`α=0.65`、`λ=0.70`。
- 问题中的细节需求使 `α` 减少 `0.15`，上下文需求使 `α` 增加 `0.15`；上下文问题还可使 `λ` 最多减少 `0.25`，从区域特征差异适度转向边缘密度。颜色、穿戴、持有等外观描述避免被错误当成纯关系上下文。
- 所有候选都保留；Top-3 只是评测预算，不是剪枝。

### 第 8 页：Stage 1——按层访问、阈值下降与候选输出

- 搜索从允许的最深层开始，再回到较浅层。
- 每一层先做 CVSearch 初始排序，再做 Query 感知重排，然后依次访问候选。
- 基础 MLLM 判断当前区域是否足以回答问题；达到上阈值时立即选中。
- 每访问固定数量的候选后，阈值按冻结步长下降，但不低于下阈值。
- 最深层可检查父区域以减少局部误检；所有候选失败时返回该层可用的最好候选，而不是凭空生成区域。
- Stage 1 输出包括候选顺序、区域坐标、排序分量、实际访问顺序和初始答案记录。

### 第 9 页：Stage 2——为什么还需要 Observation，以及 ZOOM、EXPAND 的区别

- Stage 1 解决“先看哪里”，但单个候选仍可能看不清细节或缺少关系对象。
- `ZOOM` 保持目标区域不变，从原图重新取得更高分辨率观察，用于文字、颜色、纹理和小目标细节。
- `EXPAND` 保持目标区域作为焦点，同时加入一个未访问的相邻区域，用于位置、关系和上下文问题。
- 两个动作都只产生候选 Observation，不自动改变答案；无新像素、重复区域或超出预算时动作不可用。
- 用并排示意图展示“同框放大”和“焦点加邻域”的区别。

### 第 10 页：Stage 2——支持度、答案一致性、校准和 P0 锚点

- 每个 Observation 输出三项支持概率：证据充分、部分充分和不充分。
- 原始支持度为 `p_full × sqrt(support_consistency × answer_consistency)`；答案一致性在 HR-Bench 中先把四种选项排列映射回同一个语义答案。
- 单调校准将原始支持度映射为 `P(sufficient)`，支持不确定性定义为 `1-P(sufficient)`。
- 控制器根据缺失原因选择停止、放大、补上下文或回退；缺少校准、输出不可解析、观察重复或模型异常时不替换初始答案。
- Stage 2 最终答案、原始输出和来源区域被精确重建并保存为 `P0`。后续任何阶段都必须能够无损返回它。

### 第 11 页：Stage 3——SPLIT 产生的受限分支与多尺度观察

- 当 Stage 2 已找到相关区域但内部位置仍然模糊时，`SPLIT` 才对该区域继续细分。
- Stage 3 使用冻结的有限分支、固定访问顺序和固定观察预算，不在评测时重新搜索阈值。
- 每个分支保存原图坐标、渲染哈希、查询来源、排序来源和累计观察数。
- 同一候选需要来自至少两个不同渲染的支持，单一高分观察只能让搜索继续，不能单独替换 `P0`。
- 用分支图展示紧裁剪、上下文裁剪和必要的中间尺度如何为同一候选提供独立观察。

### 第 12 页：Stage 3——不确定性驱动的状态控制与精确回退

- 风险判断使用已有的答案不确定性、多视图一致性、校准最低支持度、支持增量以及候选与 `P0` 的冲突程度。
- `CONTINUE` 表示当前证据尚有改进空间，继续暴露下一观察。
- `BACKTRACK` 表示当前分支耗尽或风险过高，转到仍未访问的分支；已经消耗的预算不恢复。
- `REPLACE` 只表示 Stage 3 提出一个满足风险条件的候选，仍需经过独立验证层。
- `STOP_P0` 和 `FALLBACK_P0` 都保留 `P0`；前者表示搜索正常结束但没有安全候选，后者表示材料或运行契约不成立。
- 本页明确不把 uncertainty 写成单一置信度，而是解释为多项风险证据共同约束替换。

### 第 13 页：独立验证层——Qwen2.5-VL-32B 的否决与确认

- 独立答题模型固定为 Qwen2.5-VL-32B，处理像素预算固定为 4,194,304。
- 输入只有完整原图、原问题和原选项；不向它展示 `P0`、Stage 3 候选、数据集名、正确答案或标注框。
- 对 Stage 3 风险控制已经接受的候选：独立答案置信度至少为 0.6 且与候选不一致时，否决候选并返回 `P0`。
- 对 Stage 3 原本回退的 observation-8 提议：候选多视图一致率至少为 0.4、独立答案置信度至少为 0.6，且两者答案完全一致时，允许确认该候选。
- 其余情况、绑定哈希不一致、推理异常或解析失败均返回 `P0`。
- 强调独立验证层不是替代 uncertainty，而是在风险判断之后增加一个候选无关的全图检查。

### 第 14 页：Qwen 上的分阶段结果

结果按不同数据范围分别报告，禁止把它们相加。

- Stage 1 Qwen 开发集：Top-3 证据召回率从 `85.71%` 提升到 `95.24%`，回答准确率从 `80.00%` 提升到 `83.33%`。
- Stage 1 v6 混合盲测：Top-3 证据召回率维持 `78.57%`，回答准确率维持 `85.00%`；该结果证明最终跨模型版本对 Qwen 无回退，不代表额外提升。Recall@1 从 `57.14%` 降至 `42.86%`，因此只主张 Top-3 目标。
- Stage 2 声明的跨模型测试：Qwen 在 V* 上从 `17/20` 到 `18/20`，在 TreeBench 上从 `5/12` 到 `6/12`；HR-4K 和 HR-8K 不下降。
- 最终接受的两分区开发检查：Qwen 净增 7 个计分单元；与 InternVL 合计为 16 次修正、0 次破坏。该检查属于已打开开发数据，不写成外部泛化证据。

### 第 15 页：MME-RealWorld-Lite 端到端结果、局限与结论

- 封存策略在读取标签前固定，并只评分一次。
- Qwen：`880/1919` 提升到 `907/1919`，即约 `45.86%` 到 `47.26%`，净增 27 题；49 次修正、22 次破坏、99 次答案替换、0 次运行失败，平均每题 8.41 个观察。
- 作为稳健性补充，InternVL 从 `879/1919` 提升到 `897/1919`，净增 18 题；两模型合计净增 45 题。
- 端到端提升归因于 Stage 1、Stage 2、Stage 3 和独立验证层的共同作用，不能全部归因于排序。
- 局限包括：Stage 1 最终盲测对 Qwen 是无回退而非提升；开发集已打开；MME 只进行一次封存评测；独立验证需要额外的 32B 模型计算。
- 结论聚焦于已经得到证据支持的主张：分阶段证据收集和保守替换在封存 MME 测试上提高了 Qwen 的最终正确数。
